**Branch**: `006-gpws-audio` | **Date**: 2026-11-11 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/006-gpws-audio/spec.md`

**Implements**:

## Summary

Original callouts (Windows text-to-speech) and a synthesized chime are generated by `tools/gen_audio.py` into
`data/audio/*.wav` (16 kHz mono PCM16) and flashed to the FAT partition with `pio run -t uploadfs`.

An `AudioService` task (core 0, prio 5):
- plays them from FFat through LilyGoLib's already-initialised I2S `Player`, exposed via new
  `IBoard::audioBegin/audioWrite/audioEnd`;
- uses our own pure WAV parser and q15 volume;
- holds `RailLease(AudioAmp)` only while sounds play, with a pop guard and a 200 ms tail;
- keeps a bounded priority queue with preemption and staleness drop.

AlertManager queues the callout on raise/re-arm, repeats warning callouts every ~6 s until acknowledged, and stops them
on acknowledge. A pure chime rule plays the cabin chime at hh:00 outside quiet hours.

Settings get a SOUND section (volume Off/1–4, hourly chime, quiet hours, Play sample).

## Technical Context

**Language/Version**: C++17 (xtensa GCC 8.4, Arduino-ESP32 2.0.17 / IDF 4.4). Host tests use WinLibs GCC 16.2.
Tooling: Python 3 (PlatformIO penv) + Windows PowerShell `System.Speech`.

**Primary Dependencies**:
- LilyGoLib `Player` (legacy I2S driver, already installed at boot);
- Arduino `FFat` (already mounted by LilyGoLib);
- **no new libraries**. `ESP8266Audio` 2.0.0 stays pinned but unused (R1); removing it is out of scope.

**Storage**:
- `ffat` partition: `/audio/*.wav` (≈300 KB);
- NVS settings schema **v6** (`volume`, `chime`, `qhstart`, `qhend`).

**Testing**:
- Unity on `env:native`:
  - `test_wav` (valid/odd chunks/rejects);
  - `test_audio_math` (gain steps, saturation);
  - `test_sound_queue` (priority, FIFO within a priority, dedupe, full-drop, stale drop, purge, preempt);
  - `test_audio_policy` (quiet hours incl. wrap and start == end; allow matrix; chime rule incl. duplicates and clock
    jumps);
  - `test_alerts` (`calloutFor`);
  - settings v6.
- On-device: quickstart Q1–Q7. The listening checks need the wearer.

**Target Platform**: T-Watch Ultra (MAX98357A-class amp on BLDO2). The T-Watch S3 must compile (same `Player` API).

**Project Type**: Embedded firmware + an asset-generation tool.

**Performance Goals**:
- callout ≤1 s after raise;
- stop ≤0.5 s;
- amplifier off ≤0.5 s after the last clip;
- chime at hh:00 ±2 s;
- PFD median ≥28 fps during playback.

**Constraints**:
- amplifier rail only via PowerService (constitution III);
- I2S only in `src/board/`;
- no audio work on the UI task;
- internal heap ≥40 KB;
- clips original/TTS (VI).

**Scale/Scope**:
- 5 core modules (Wav, AudioMath, SoundQueue, AudioPolicy, + Alerts extension);
- 1 service + task;
- IBoard +3;
- a Settings section;
- ~7 serial commands;
- 1 tool script;
- 8 assets;
- ADR-013.

No NEEDS CLARIFICATION remains (research R1–R8). `uploadfs` for fatfs on this platform version is **verified first**
(R2 fallback ready).

## Implementation Notes (for /speckit-tasks)

1. **Order:**
   1. **Verify `uploadfs` for fatfs first:** put a test file in `data/`, run `uploadfs`, check that FFat lists it on
      boot. If it fails, take the R2 fallback.
   2. `tools/gen_audio.py` and the assets.
   3. Core tests → core.
   4. IBoard audio + AudioService with `ad audio play`.
   5. **Checkpoint:** hear a clip, `amp ON/OFF` timing, no pop.
   6. AlertManager callouts.
   7. Chime.
   8. Settings.
   9. Docs and validation.
2. **Pop guard and tail** are tuned on the device: try 30 ms settle / 20 ms zeros. Record the values in
   `validation.md`.
3. **Mono on `ALL_RIGHT`:** LilyGoLib configured `I2S_CHANNEL_FMT_ALL_RIGHT`. `configureTX(rate, 16, MONO)` with mono
   samples. If the output plays at the wrong speed (stereo slot), duplicate samples into L/R instead. Verify on the
   device by ear and by duration (`ms=` vs the expected value).
4. **The factory MP3s on `ffat` are replaced by `uploadfs`** (the whole image). Mention this in the README.
5. **Measure:** latency raise → `[aud] play` (log timestamps), `amp OFF after`, FPS during playback.
6. **At the end:** update `docs/product_roadmap.md` per the status tracking rule (S5 → ✅; M2 stays 🚧 until S6).
