# ADR-013: Audio assets are flashed with `uploadfs`; FFat is read in services as a platform service

- **Status:** Accepted (slice S5, 2026-11-12)
- **Amends:** ADR-009 (its consequence "copy over USB mass storage")
- **Relates to:** constitution Principles II (layering), VI (original audio), VII (reproducible);
  AD-SAS-001 §4, §6, §7.1

## Context
- ADR-009 put assets on LilyGoLib's FAT partition `ffat` and assumed the wearer could copy files over **USB mass
  storage**.
- LilyGoLib compiles its MSC export only `#if !ARDUINO_USB_MODE`. Our board JSON sets `ARDUINO_USB_MODE=1` (hardware
  CDC/JTAG), which the serial console needs. So USB drag-and-drop does not exist in this firmware.
- S5 needs eight WAV clips (≈290 KB) on the watch, reproducibly from a clean checkout.
- LilyGoLib mounts FAT at boot (`FFat.begin(false, "/fs")`, formatting it if the mount fails) and installs the legacy
  I2S driver for its `Player` (`initAmplifier()`), unless `NO_HW_MIC` is passed.

## Decision
- **Assets live in the repository** under `data/audio/*.wav`, generated by `tools/gen_audio.py` (Windows offline
  text-to-speech + a synthesized chime; no third-party audio).
- They are flashed with **`pio run -e twatch_ultra -t uploadfs`**. `board_build.filesystem = fatfs` makes PlatformIO
  build a FAT image of `data/` and write it to the `ffat` partition. Verified on espressif32@6.12.0 (S5 T003/T016:
  all 8 clips read back with valid headers).
- **FFat is a platform service** (same reasoning as ADR-012): the FAT filesystem on the SoC's own flash is identical
  on every board, so `FFat.h` is used only in `src/services/AudioService.cpp`, never in core/ui/pages.
- **The speaker stays behind `IBoard`**: `audioBegin(rate)`, `audioWrite(samples, n)`, `audioEnd()` wrap LilyGoLib's
  already-installed `Player` (no second I2S owner, ESP8266Audio not used). The amplifier rail is
  `Rail::AudioAmp`, switched only by `PowerService` through a `RailLease` held while sounds play.

## Consequences
- `uploadfs` writes the **whole** partition: the LilyGoLib factory MP3s are removed (they were unused).
- Flashing assets is a separate, documented step (README). Firmware without the assets still runs, silently; each
  missing clip is logged once (FR-015, SC-006).
- A failed FAT mount makes LilyGoLib format the partition at boot: the clips then show `MISSING` in
  `ad audio list` until `uploadfs` is run again.
- `ad simfail mic` also removes the speaker (LilyGoLib's single `NO_HW_MIC` flag skips the amplifier init).

## Alternatives
- **Switch to TinyUSB (`ARDUINO_USB_MODE=0`) for USB mass storage:** breaks the HW-CDC serial console used by every
  validation script. Rejected.
- **Serial upload helper (`ad fs put`):** kept as the fallback of research R2; not needed because `uploadfs` works.
- **Embed the clips in the firmware image:** ≈290 KB more per OTA slot and a rebuild for every voice change.
  Rejected.
